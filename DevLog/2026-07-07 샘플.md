# 2026-04-15 Docker vs Local venv 구조 차이 (uv sync 오류)

> FastAPI 프로젝트를 Docker로 옮긴 뒤 VS Code가 Python 인터프리터를 못 잡고,
> 로컬에서 `uv sync` 가 깨진 하루. 원인을 찾아 **Named Volume 격리 패턴**으로 정리함.

## 증상

- `docker compose up` 은 정상. 컨테이너 안에서는 앱이 잘 뜸.
- 그런데 호스트(Windows) VS Code에서:
  - 인터프리터 선택 목록에 `.venv` 가 뜨는데, 고르면 `python.exe` 를 못 찾음.
  - 로컬 터미널에서 `uv sync` 실행 시 `pyvenv.cfg` 경로 불일치로 실패.

## 조사

1. 프로젝트 루트에 `.venv/` 가 생겨 있음. 근데 안이 `bin/` 구조 (Windows면 `Scripts/` 여야 함).
2. `pyvenv.cfg` 열어보니 `home = /usr/local/bin` — **컨테이너 내부 경로**가 박혀 있음.
3. `docker-compose.yml` 확인:
   ```yaml
   volumes:
     - ./:/app          # 로컬 전체를 컨테이너에 bind mount
   ```
   → 컨테이너에서 만든 Linux `.venv` 가 bind mount 를 타고 **호스트로 새어 나온 것.**
4. VS Code 가 이 Linux `.venv` 를 로컬 venv 로 착각 → Windows 경로(`Scripts/python.exe`) 를 못 찾아 에러.

## 원인

`./:/app` 한 줄 bind mount 라 코드뿐 아니라 `.venv` 까지 양방향 동기화됨.
OS/아키텍처가 다른 venv 바이너리를 호스트-컨테이너가 공유하려 해서 충돌.

## 해결

`.venv` 경로만 Named Volume 으로 덮어써서 격리:

```yaml
services:
  app:
    build: .
    volumes:
      - ./:/app
      - venv_data:/app/.venv   # .venv 만 따로 격리

volumes:
  venv_data:
```

- 더 구체적인 하위 경로(`/app/.venv`) 마운트가 우선 적용됨 → 호스트에 `.venv` 안 생김.
- 호스트 로컬 개발용 venv 는 `uv venv` 로 따로 만들어 VS Code 에 연결.
- `.dockerignore` 에 `.venv/` 추가.

적용 후 VS Code 인터프리터 정상 인식, `uv sync` 오류 해소.
